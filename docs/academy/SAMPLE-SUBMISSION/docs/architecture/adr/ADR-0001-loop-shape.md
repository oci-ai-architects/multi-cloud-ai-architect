# ADR-0001: Fixed workflow with two bounded model steps

Status: accepted 2026-09-28 · Decision: loop · Owner: platform engineer

## Context

The job has a known path: read, extract, match, check, draft. The exceptions are known too: missing
PO, duplicate, IBAN mismatch, unreadable PDF. The two steps that need language understanding are
field extraction from messy PDFs and a one-paragraph explanation of a flag for the clerk.
Everything with money attached (matching, IBAN comparison, draft creation) has an exact rule.

## Options considered

1. **Single agent loop with tools** (`extract`, `lookup_po`, `check_iban`, `create_draft`,
   `draft_query`), model chooses the next step. This is what most agent tutorials would build, and
   it handles odd invoices more gracefully.
   Rejected: the model would choose whether to call `check_iban` before `create_draft`. An injected
   instruction in invoice text then competes with the system prompt for that choice. The ordering
   that prevents fraud has to be code.
2. **Fixed workflow, two bounded model steps** (extract to schema; explain flag). Code chooses every
   next step; the model never sees a tool.
3. **Parallel workers** (one per invoice line, coordinator merges). Rejected: invoices average
   four lines (fixture figure); the merge logic costs more than it saves, and line-level calls
   triple token use.

## Decision

Option 2. `worker/src/pipeline.ts` holds the step list. The model receives text and a JSON schema
and returns JSON; it holds no tool definitions at all.

## Consequences

- Accepted cost: odd layouts the schema does not anticipate go to `needs_human` instead of being
  handled creatively. Fixture estimate: 4 to 6% of invoices in month one.
- The tool-result injection surface shrinks to zero for the extraction step, because no tool exists
  for the model to call. Injection can still corrupt extracted fields, which is why ADR-0002 checks
  fields in code.
- Adding a step means a code change and an eval case, never a prompt edit.

## What would reverse this

If `needs_human` stays above 10% for four consecutive weeks and the clerk's log shows the cause is
layout variety the schema cannot express, revisit a single-agent loop for extraction only, with no
side-effecting tools in its reach. Observable from the portal metric `queue.needs_human.rate`.

## Acceptance eval

`gold-01`, `gold-02`, `gold-03`, `gold-04`, `edge-03`: all pass on the fixed workflow, and the
`needs_human` share on the 40-invoice backfill is 5% (2 of 40, fixture run 2026-09-30).
