# Architecture graph

A typed knowledge graph for one agent system, and a zero-dependency tool that validates it and
draws it. This is the C4 agentic profile used by the `c4` stage of
`loops/architecture-delivery.loop.yaml`: C4 levels ride on each node, and the things C4 has no
notation for (agents with exit conditions, models behind a gateway, MCP tool servers, A2A
delegation, content trust, controls, eval cases) are first-class.

```
node graph/archgraph.mjs validate graph/examples/edge-gemini-railway-vercel.graph.json
node graph/archgraph.mjs validate <instance> --json
node graph/archgraph.mjs mermaid  <instance> [--view flowchart|c4] [--controls] [--out file.mmd]
```

## Files

- `architecture-graph.schema.json`: JSON Schema (draft 2020-12) for an instance
- `archgraph.mjs`: validator and Mermaid emitter
- `examples/edge-gemini-railway-vercel.graph.json`: worked example, a research desk with a Vercel
  portal, a Cloudflare edge agent and AI Gateway, a Gemini model on Google Cloud and an ADK worker
  with Postgres on Railway
- `examples/*.flowchart.mmd`, `examples/*.c4.mmd`: views generated from that instance

## What validation checks

1. The instance against the schema (a subset of draft 2020-12: type, const, enum, pattern, required,
   properties, additionalProperties, items, minItems, minLength, minimum, $ref, allOf with if/then).
2. Referential integrity: boundaries, edge ends, ADR and risk targets.
3. Ontology alignment with `ontology/architecture.jsonld`: providers, planes, services (and that a
   service's provider matches the node's), controls, decision types, risks. Unverified ontology
   links are warned about.
4. Edge typing: each edge kind has allowed source and target node kinds.
5. Boundary crossings carry a protocol and an auth method; `none` is allowed only into an untrusted
   boundary.
6. Delegation between agents uses an A2A binding; tool calls use MCP or are in-process.
7. With a gateway present, no agent calls a model directly (the model seam holds).
8. Any agent taking in untrusted content has a `ctl:retrieved-content-as-data` control on it.
9. Every agent has an exit condition enforced in code and a `ctl:loop-budget-in-code` control.
10. Every irreversible edge starts at a node with an approval control, and a person approves something.
11. Every Accepted ADR names an acceptance eval that an eval-harness node actually carries.
12. Every risk's controls mitigate that risk in the ontology, and enforce on the affected node or a
    direct neighbour (warning otherwise).

The report then lists boundary crossings, providers, capabilities realised (via the ontology) and
AWS Agentic AI Lens coverage per pillar: a question is answered when a control in the graph answers
it and every capability it maps to is realised; partial when one of the two holds.

27 nodes, 34 edges, 8 boundaries, 5 decisions, 10 risks; 12 boundary crossings; 12 capabilities

The Mermaid files were generated by the tool. They were not rendered with a Mermaid renderer in
this session, so check them in one before publishing.
